# Monoptah web app: roadmap

Phased tickets for the program described in [README.md](README.md). Names (routes, tables, frames, F/X/N feature IDs) come from [architecture.md](architecture.md) and [features.md](features.md).

Sizes: S = up to 2 days, M = 3 to 5 days, L = 1 to 2 weeks, XL = more than 2 weeks (split before starting). One person, rough.
Risk: low, med, high, each with its reason.
Ticket prefixes: S spike, A accounts, R relay and desktop transport, E end-to-end tests, H desktop hardening, W web MVP, P push, U later.

### 0.3 Test and deploy boundaries

| Rule | Detail |
|---|---|
| Sandboxes and agents run only local tests | vitest with the Workers pool, `wrangler dev` local with Miniflare (local D1 and DO), cargo tests per the repo's native rules, the Playwright harness E-01. They never deploy and never hold Cloudflare credentials |
| CI builds and tests | CI never deploys and holds no Cloudflare deploy token (A-10) |
| Production deploy | Only the maintainer, with `pnpm deploy:official` from their Mac (A-11) |
| Native Dev E2E | E-02 runs on the maintainer's Mac before each phase gate |

Rule from the repo guidelines: one review per request, Opus reviews the diff against this ticket's acceptance list; high-risk tickets (tokens, secrets, crypto, deletion, billable lifecycle) get a separate review.
