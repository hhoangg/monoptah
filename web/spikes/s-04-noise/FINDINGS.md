Status: all acceptance criteria PASS locally (2026-11-17). Implementation under test:
`web/app/src/link/noise.ts` (WS-L, unmodified). Counterpart: `snow` 0.10.0 (crates.io, default pure Rust resolver:
chacha20poly1305, curve25519-dalek, sha2). Protocol: `Noise_IK_25519_ChaChaPoly_SHA256`.

## Vector files and schema

- `vectors/monoptah-ik.ts.json` is written by `gen-ts-vectors.ts` (keys 0x01..0x05 repeated, fake). `vectors/monoptah-ik.snow.json` is written by
  `cargo run --bin gen` (keys 0x11..0x15). Same schema (`schema.ts`, `rust/src/lib.rs`), different keys, ids and payloads.
- Cases: `plain-empty-prologue-empty-payloads`, `monoptah-prologue-with-payloads`, `max-size-transport`, `rekey-each-direction`;
  negatives: `wrong-prologue`, `wrong-responder-static`.
- Ciphertext is always stored as hex (a ciphertext is not a repeated byte); the max-size case makes each file about 280 KB.
  Plaintext uses the `{fill, length}` form when uniform.

## Spec divergences and findings about noise.ts

- No divergence from the Noise spec found: every message and hash matches snow and cacophony bit for bit, including empty payloads,
  empty prologue, the 65,535-byte transport message and rekey.
- Nonce limit: `CipherState` throws `nonce_exhausted` for both encrypt and decrypt at nonce 2^64-1, `setNonce` is public so it is
  reachable without 2^64 operations. `rekey()` is allowed at the limit (it uses nonce 2^64-1 internally per spec 4.2) and does not reset the nonce.
- snow 0.10.0 at the limit: `StatelessTransportState::write_message(u64::MAX, ..)` returns `Error::State(StateProblem::Exhausted)`, as does a
  stateful `read_message` after `set_receiving_nonce(u64::MAX)`; `u64::MAX - 1` works and the receiving nonce becomes `u64::MAX`. The sending
  nonce of a stateful `TransportState` has no public setter, so the encrypt refusal is only reachable through the stateless API.
- Minor, not a bug: `HandshakeState` of noise.ts has no way to read the responder's received message-1 payload other than the return value of
  `readMessage` (fine). `generateKeyPair(privateKey)` copies the key and does not clamp it (x25519 in @noble clamps internally, same as snow).

## Proposed `noise` section for web/protocol/vectors.json (handoff to WS-K, via gen-vectors.ts)

WS-K owns `web/protocol/vectors.json`. Proposal: add a top-level `noise` key with exactly the shapes below, using the same byte-string forms
as the rest of the file. Keep two files in the spike dir as the source of truth, or let gen-vectors.ts re-generate the `ts` side from noise.ts and import
the `snow` side and the published side as data:

```json
"noise": {
  "protocol": "Noise_IK_25519_ChaChaPoly_SHA256",
  "cases": [ { "name", "source": "ts" | "snow", "prologue", "initiator": {"static","ephemeral"}, "responder": {"static","ephemeral"},
               "publicKeys", "handshake": [ {"payload","message"}, {"payload","message"} ], "handshakeHash": {"initiator","responder"},
               "transport": [ {"from","plaintext","ciphertext"} | {"rekey": "initiator->responder" | "responder->initiator"} ] } ],
  "negative": [ { "name", "kind", "initiatorPrologue", "responderPrologue", "initiator", "initiatorRemoteStatic", "responderStatic", "message1" } ],
  "published": [ { "source", "...fields exactly as in published-ik.json" } ]
}
```

Rules to state in the `$comment`: a key in `initiator`/`responder` is an X25519 private key (fake), `ephemeral` is the fixed ephemeral private key
(use `ephemeralPrivateKey` in noise.ts, `fixed_ephemeral_key_for_testing_only` in snow); `from` names the sender; a `rekey` step rekeys the sender's
send state and the receiver's recv state of that direction; a negative case passes when the responder fails reading `message1`. Remove the line
"Noise handshake vectors are not part of this file yet" from `$comment` and teach `frame.rs`/TS suites to ignore the new key until they use it.
The Rust helpers in `web/spikes/s-04-noise/rust/src/lib.rs` (`replay`, `replay_negative`) and `replay.ts` are the reference consumers.
Size note: the file would grow by about 560 KB with two max-size cases; consider keeping only one max-size case in `vectors.json` or using a digest form.

## Commands

```bash
# TS side (from web/): regenerate the TS vectors, run the S-04 tests
node spikes/s-04-noise/gen-ts-vectors.ts
pnpm --filter @monoptah/spikes exec vitest run s-04
# Rust side (from web/spikes/s-04-noise/rust): regenerate the snow vectors, run the tests
cargo run --bin gen
cargo test
# Regenerating either file and committing the result is how the vectors change; both suites fail if a committed file is stale.
```

The Rust crate has its own `[workspace]`, a committed `Cargo.lock`, and builds into `rust/target` (git-ignored by the root `target/` rule).
