01 / PRODUCT CONTRACT

Thiết lập một lần. Mỗi task có môi trường riêng.

Docker là execution backend. Repository và environment thuộc project. Agent/account được chọn ở session. Các phần này không gắn cứng với nhau.

Trong v1

  • Native app quản lý list/create/status/stop/resume/delete bằng sbx --cloud.
  • GitHub, GitLab.com / GitLab self-managed và Bitbucket Cloud qua HTTPS token; public repo có thể dùng anonymous.
  • Devcontainer từ image, Dockerfile, Features và Compose; chỉ công bố support sau khi qua compatibility tests.
  • Bootstrap Claude Code + Monoptah Host vào môi trường development, kết nối qua transport riêng.
  • Chat, transcript, approvals, files và Git dùng remote session experience hiện có trong phạm vi host hỗ trợ. Lưu ý: với cloud session Codespaces trên main, Explorer/Changes vẫn hiển thị checkout local (banner "Local files - this session runs in codespace ...") và Git write local bị khoá (crates/monocode-gpui/src/git_gate.rs); muốn Files/Git của sandbox là phần việc mới.

Không nằm trong v1

  • Git SSH keys/agent forwarding; mật khẩu tài khoản Git; nhận SSH host do user nhập cho Docker backend.
  • Codex hoặc agent khác trên Docker: kiến trúc để mở, UI chưa cho chọn khi chưa được kiểm chứng.
  • Bitbucket Server/Data Center; API tạo PR/MR đa nền tảng; auto-merge hoặc tự động push.
  • Đồng bộ hai chiều working tree laptop ↔ cloud, upload uncommitted files tự động.
  • Tái tạo nguyên trạng mọi devcontainer/Codespaces extension, hardware hoặc host integration.
Ranh giới “SSH”: loại bỏ SSH cho Git authentication. App vẫn dùng SSH do Docker CLI cung cấp để bootstrap/tunnel vào sandbox; user tự chạy sbx login và sbx --cloud setup ssh một lần trên máy (sau đó SSH dạng ssh <sandbox-id>@sbx_cloud). App không chạy login hay setup thay user, chỉ kiểm tra và hướng dẫn.

Phạm vi, UX và defaults đã chốt. Provisioning dùng lại flow/UI Codespaces hiện có; không thiết kế UI riêng cho Docker. Các release gates kỹ thuật vẫn phải kiểm chứng trước khi phát hành: PoC hiện chỉ xác nhận devcontainer, chưa xác nhận toàn bộ agent/auth/host.

03 / END-TO-END FLOW

Từ cấu hình đến session dùng được

Chuẩn bị trên máy

User cài sbx, login Docker, setup cloud SSH. App chỉ diagnose/check (sbx --cloud diagnose: CLI, sign-in, API, account access), không mở login flow hoặc ghi SSH config ngầm. Kiểm tra cả network policy của account (sbx --cloud policy ls).

Credential dùng lại

Tạo Git profile: platform, host, username, token. Agent account cấu hình riêng. Project chỉ lưu secret references.

Cloud setup theo project

Chọn HTTPS repo, credential, base ref, devcontainer, secret bindings, architecture, compute và runtime limit.

New feature session

Trong composer của session mới: menu Workspace (dưới composer) chọn Local, Codespace hoặc Docker Sandbox; chọn base branch, compute rồi bấm "Create and open" (có thông báo trả phí). Như Codespaces: session có ngay, step list chạy đến Ready, prompt gõ trong lúc chờ được queue bằng queue_start_message và gửi một lần sau Ready.

Provision & clone

Ghi request ID → tạo Shell sandbox → persist sandbox ID ngay → SSH → cấp Git helper → clone ref và tạo feature branch.

Build environment

Chuẩn bị Dev Container CLI → resolve private registry bindings → devcontainer up → Features/Compose/lifecycle → readiness checks.

Agent + Host

Trong devcontainer: cài Claude nguyên bản, host đúng app version + bundled Node, cấp auth và Git helper, pair/tunnel riêng → Ready.

Develop → archive → delete

App chat/files/Git qua host. Reconnect dùng ID cũ. Hoàn tất: review diff, push khi user yêu cầu, archive history, xác nhận rồi xoá.

Readiness là điều kiện, không phải timer

Chỉ mở session tương tác khi đúng workspace/user, CLI Claude chạy được, host health/auth/capabilities hợp lệ, đường kết nối riêng hoạt động và project lifecycle hoàn tất.

Nếu user nhập prompt trong lúc provision: giữ draft bằng queue_start_message, gửi đúng một lần sau Ready. Không chạy setup-token hay tự gửi model request để “test auth” khi chưa có hành động user rõ ràng.

Source of truth nằm trên cloud

Clone Git ref đã commit, không upload working tree laptop. Trong một feature session, workspace/branch cố định; mỗi session Docker mới có sandbox riêng.

Mở lại cùng session → reconnect/resume sandbox cũ. Tạo session mới → sandbox mới. Đổi config project chỉ áp dụng session tạo sau.

Repository trust: devcontainer/Dockerfile/lifecycle là code được chạy. Trước lần đầu chạy một config/ref chưa được tin cậy, hiển thị repo + ref + config và credential bindings sẽ được cấp. Không chạy project scripts ở bước Validate. Chỉ cấp agent token sau build; secret cần cho build phải được liệt kê riêng.
04 / CONFIGURATION & AUTH

Profile một lần, binding theo project

Nơi lưu Dữ liệu Quy tắc
Git credential profile ID, label, platform, exact HTTPS origin, username, secret reference, expiry metadata nếu biết Secret mã hoá AES-256-GCM trong SQLite của app, key ở credentials.key (0600), cùng cơ chế với account Claude (accounts/token.rs); không dùng Keychain, không sync lên Monoptah backend. Không lưu vào repo hoặc settings JSON plaintext. Khác tài khoản trên cùng host có profile riêng.
Project cloud config Repo URL, credential profile ID, base ref, devcontainer path, secret bindings, compute, architecture, timeout action Thông tin không mật. Credential binding có thể theo host + repo path. URL chứa token/password bị từ chối; không tự redirect secret sang origin khác.
Agent selection Provider ID + account reference; default provider có thể đặt theo project V1 chỉ Claude Code được enable trên Docker. Token/cách login không nằm trong repository profile. Các phương thức auth tương lai do agent adapter chịu trách nhiệm.
Session snapshot Local session ID, create request ID, sandbox ID/name, config version, resolved base commit, branch, host environment/session ID, provisioning checkpoint Persist trước/sau các side effect quan trọng để khôi phục. Không chứa raw secrets, command argv hoặc log có token.
Devcontainer trong Git Image/Dockerfile, Features, Compose, workspace/runtime/env không mật và lifecycle Giữ portable, không nhét cấu hình sbx hoặc agent account bắt buộc vào repo. App overlay công cụ host/agent; không sửa tracked devcontainer tự động.

HTTPS token adapters v1

Platform Git HTTPS credential Phạm vi / kiểm tra
GitHub GitHub username + personal access token Repo phải thuộc quyền token; clone/fetch và push phụ thuộc quyền riêng. Fine-grained permissions, SSO/org approval có thể cần. API tạo PR không nằm trong generic Git auth.
GitLab Username không rỗng + access token; PAT có thể dùng oauth2 làm username GitLab.com và self-managed HTTPS. Gợi ý read_repository/write_repository cho PAT phù hợp. Không mặc định cấp API scope rộng.
Bitbucket Cloud API token có scopes + username hoặc x-bitbucket-api-token-auth Clone cần read:repository:bitbucket; push thêm write scope. Không dùng account password/app passwords cũ. Server/DC để ngoài v1.

“Check repository access” chỉ kiểm tra read bằng thao tác Git read-only, không push thử hoặc tạo branch trên remote. Read thành công không chứng minh write permission; UI phải nói rõ.

Cấp token cho sandbox mới

  1. App giải mã profile từ store của app tại thời điểm provision.
  2. Chuyển qua kênh authenticated/private; không token trong argv, clone URL, prompt hay log.
  3. Git helper/broker trong sandbox giữ credential trong memory, cấp theo exact host/path đã bind.
  4. Helper dùng được ở outer sandbox lúc clone và bên trong devcontainer cho fetch/push, kể cả app disconnect.
  5. Process restart mất memory → cần app cấp lại; hiển thị “Credential required”, không fallback sang password hoặc profile khác.

Đây là thiết kế đề xuất cần PoC riêng. Không hứa snapshot an toàn: memory checkpoint có thể chứa token. Agent chạy cùng OS user có thể sử dụng credential được cấp; không coi helper là isolation tuyệt đối.

Agent authentication

V1 chạy Claude Code do Anthropic phát hành, không sửa binary. Không tạo flow setup-token mới trong sandbox. Codespaces trên main đặt CLAUDE_CODE_OAUTH_TOKEN làm user codespace secret qua gh (giá trị chỉ đi qua stdin); bootstrap restart Host khi hash token đổi. Dialog Codespaces setup chạy claude setup-token trong terminal nhúng và tự bắt token từ output (crates/monocode-gpui/src/codespaces_dialog.rs); named accounts (PR #52) lưu setup-token/API key mã hoá trong DB local và chỉ inject cho process Claude local. Docker chưa có kênh tương đương được xác nhận.

Setup-token có hạn một năm, chỉ dùng cho model requests (không Remote Control, không claude.ai connectors) và yêu cầu plan Pro/Max/Ultra/Team/Enterprise. Bare mode không đọc CLAUDE_CODE_OAUTH_TOKEN.

Chốt v1: dùng account Claude đã cấu hình trong app (ClaudeCredential của PR #52). Setup-token → CLAUDE_CODE_OAUTH_TOKEN, API key → ANTHROPIC_API_KEY; adapter chỉ đặt đúng một biến cho Host/Claude trong devcontainer và gỡ biến còn lại cùng ANTHROPIC_AUTH_TOKEN: với setup-token, hai biến API key/auth token thắng CLAUDE_CODE_OAUTH_TOKEN trong thứ tự auth; với API key, gỡ token OAuth để biết chắc nguồn tính phí. Không login hay chạy setup-token trong sandbox.

Docker cloud credentials chỉ tài liệu hoá đường Anthropic API key (sbx --cloud secret set anthropic, proxy gắn header). App không dùng secret store này mà tự đặt env, nên cần PoC rằng request của Claude với CLAUDE_CODE_OAUTH_TOKEN đi qua network policy/proxy của Docker cloud mà không bị chặn hoặc ghi đè header.

Điều khoản Anthropic cho phép end user đăng nhập binary nguyên bản bằng subscription của chính họ, kể cả khi platform host Claude Code; nhưng cấm developer thu thập, lưu hoặc intermediate Claude.ai credentials/session tokens và khuyến nghị API key cho sản phẩm.

Release gate: kiểm chứng kỹ thuật và làm rõ cách lưu/chuyển token được phép. Flow Codespaces hiện có (app chuyển token vào codespace secret) cũng thuộc cùng câu hỏi điều khoản, nên không được coi là bằng chứng hợp lệ cho Docker cloud.

Private registry, package secrets, submodules và custom CA

Registry auth cần trước khi pull/build devcontainer, không chỉ sau khi host Ready. Docker cloud secret commands không hỗ trợ registry credentials, nên app phải tự cấp (ví dụ docker login qua stdin trong outer sandbox) và đó là phần cần PoC. Package credentials chỉ cấp ở bước cần, không qua Docker build args/layers. Cấu hình secret references theo host và mục đích; không commit giá trị vào .npmrc, Compose hoặc image.

V1 phát hiện private submodule/LFS domain chưa có binding và dừng rõ “Additional repository credential required”. Không gửi token chính sang domain khác. Các tổ hợp này phải qua compatibility tests riêng trước khi công bố hỗ trợ.

Self-managed HTTPS cần CA/proxy được cấu hình riêng nếu có; không tắt TLS/host verification. URL SSH/local path không được nhận cho Docker source v1.

05 / STATE & RECOVERY

Không tạo lại sandbox khi chỉ mất kết nối

Preflight → Create → Provision → Build container → Lifecycle commands (waitFor) → Configure environment → Connect over SSH → Open project → Ready (Background lifecycle commands chạy tiếp, không chặn Ready)
Ready ↔ Disconnected (task có thể vẫn chạy)
Ready → Stopping → Stopped → Resuming → Connect over SSH → Ready
Failed(step) → Retry (cùng sandbox ID nếu còn tồn tại) hoặc Rebuild (dựng lại devcontainer trong cùng sandbox)
Ready / Failed / Stopped → Archiving (convert) → Keep running / Stopped (mặc định) / Deleted (history read-only)
Any live state → Missing / Expired (không tự tạo và replay prompt)

Các state provisioning hiển thị qua StepKind và StartRecord hiện có (mục 06), không thêm state machine UI riêng. Stopped/Missing dùng lại CloudState.

Trường hợp Hành vi bắt buộc
Save setup / Validate Không provision, không compute charge, không chạy lifecycle. Thiếu sbx/login/SSH → hướng dẫn lệnh user tự chạy, có Recheck.
Create timeout / app crash Không create mù lần nữa. Reconcile bằng request/session name + persisted ID; claim lại sandbox khớp. Không attach sandbox cùng tên nhưng khác ownership metadata.

Devcontainer build/lifecycle lỗi Hiển thị stage + redacted logs. Retry cùng sandbox, bảo vệ thay đổi workspace; rebuild có cảnh báo data container. Cho Stop hoặc Delete rõ ràng.
Desktop ngủ / tunnel mất Hiển thị Disconnected, không coi task đã dừng. Reconnect cùng host/session, nhận transcript mới; giữ command IDs để tránh gửi prompt hai lần.
Stop / runtime limit Stop là tạm dừng cả agent, devcontainer và infra. App theo dõi trạng thái thực đến stopped; không hứa tiếp tục model/tool request đang dở. Khi resume phải reconcile provider operation, không tự replay.
Runtime limit hết khi user offline Luôn truyền --on-timeout stop tường minh: nếu bỏ trống, server stop sandbox resumable và xoá phần còn lại. TTL là wall-clock runtime limit, không phải idle timer; mỗi lần resume bắt đầu một TTL mới. Chỉ dùng non-volume-backed sandbox v1 (volume-backed không stop được; hành vi của --on-timeout stop với loại này chưa rõ).
Runtime limit sắp hết khi đang có turn Hiển thị thời gian còn lại trước khi hết hạn. Gia hạn chỉ khi user bấm (sbx --cloud ttl +<duration>); Docker không cho gia hạn quá 24 giờ kể từ lúc tạo. Không tự gia hạn.

Archive (Stop / Delete) Cùng flow Codespaces: cancel/wait active turn → convert sang local session đã archive (transcript, JSONL, bundle/patch code chưa push) → nếu còn file chưa lưu thì review "Delete anyway" / "Stop instead" → stop hoặc xoá đúng sandbox ID → verify. Không push, xoá branch remote hay xoá project credential.
Archive lỗi / host unreachable Không báo archive đầy đủ và không xoá tự động. Giữ sandbox, cho reconnect/resume rồi retry. Nếu user vẫn muốn xoá: confirmation riêng nói rõ mất history/data chưa tải.
Sandbox bị xoá bên ngoài Đánh dấu Missing, giữ local metadata/history đã sync. Tạo replacement là hành động mới có charge và workspace mới; không giả vờ resume task cũ.
Network policy chặn egress Policy account/sandbox (allow-all, balanced, deny-all) có thể chặn Git host, Anthropic API, claude.ai/install.sh, GitHub release của Host, registry/Features. Preflight liệt kê các destination cần; khi lỗi hiển thị stage + host bị chặn (gợi ý sbx --cloud policy log), không tự sửa policy của user.
Stop/resume báo "not found" Docs: operation có thể bị tắt cho account. Không coi là Missing ngay; inspect theo ID rồi mới kết luận, không create thay thế.
Gửi prompt khi sandbox Stopped Codespaces hiện tự wake khi user gửi/retry (cloud_wake.rs, ensure_before_send). Với Docker, resume tốn compute: chỉ resume theo hành động user, không resume từ background polling. --env và --allow-network bị từ chối khi resume, nên mọi env/network rule phải đặt lúc create.

Default v1: small 2 CPU/4 GiB (cũng là default của Docker), runtime limit 2 giờ (Docker default là 1 giờ nên app phải truyền --ttl), timeout stop. Không tự gia hạn TTL làm tăng chi phí. Architecture lấy từ project/session đã chọn qua --platform linux/arm64|linux/amd64 trong phạm vi account hỗ trợ; PoC chỉ chạy ARM64, không mặc định mọi image đều có ARM64.

06 / NATIVE INTEGRATION

Tổng quát hoá cloud session Codespaces, thêm Docker backend

main đã có GitHub Codespaces đầy đủ trong native app. Cloud session là remote session bình thường (remote://<env>/workspaces/<repo>) mà store::RemoteProject mang binding local_project + codespace; chat, composer, stop, archive đi qua remote session path có sẵn. Docker Sandbox là backend thứ hai của cùng flow này, không phải manager tách rời.

Dùng lại (có sẵn trên main)

  • crates/monocode-core/src/cloud_sessions.rs: CloudSessions, CloudBinding, CloudState, SessionTarget, ensure_before_send (chỉ wake khi user gửi/retry), require_claude (Claude-only), stop/delete, pull_evidence.
  • cloud_sessions/startup.rs: non-blocking start begin_start → run_start (idempotent cho first run, Retry và resume sau restart); Rebuild gọi rebuild_start để reset steps rồi chạy lại run_start; StartRecord persist ở setting cloud-starts.v1; prompt gõ khi đang start được giữ bằng queue_start_message.
  • cloud_sessions/convert.rs: archive trước khi stop/delete. Sync transcript, pull .evidence, stage JSONL của Claude, git bundle commit chưa có trên remote, patch thay đổi chưa commit (kể cả untracked) vào một local session đã archive; restore_code khôi phục.
  • UI: cloud_start_view.rs, transcript/cloud_start.rs, codespace_pane.rs (tab RightTab::Codespace), shell/cloud_start.rs (Retry, Rebuild, Open in browser, Delete, View log), shell/cloud.rs (dialog "Archive cloud session?" với Keep running / Stop / Delete, cảnh báo "Some files are not saved"), cloud_wake.rs.
  • Remote host: crates/monocode-core/src/remote.rs, remote/ssh.rs (tunnel, pairing, codespace_bootstrap_script), remote/remote_bootstrap.sh (cài Host đúng version có checksum, cài Claude Code nếu thiếu, restart Host khi hash CLAUDE_CODE_OAUTH_TOKEN đổi), store/remote.rs, host/child-backend.ts.

Cần làm mới cho Docker

  • Backend seam: core hiện gắn cứng Codespaces (GhRunner, StartRecord.codespace, RemoteProject.codespace, SshTarget.codespace, endpoint codespace://, CODESPACE_NOT_CONNECTED). Cần một trait backend (create/state/stop/resume/delete/log/ transport) với Codespaces là implementation đầu tiên.
  • sbx runner tương đương codespaces.rs (injectable cho test, secret chỉ qua stdin), dùng sbx --cloud create/ls/inspect/exec/stop/rm/ttl; resume qua attach/run --name (không có lệnh start; sbx --help v0.51.0: attach "starting it first if it is stopped"). Luôn chạy với --no-input để lệnh cần hỏi sẽ fail thay vì treo.
  • Transport hai lớp: gh codespace ssh vào thẳng dev container, còn ssh <id>@sbx_cloud vào outer Shell sandbox. Cần wrapper devcontainer exec để bootstrap Host đúng container/remoteUser/home và route port Host của container ra loopback của outer sandbox.
  • Repo URL HTTPS + Git credential profile + broker: Codespaces lấy repo từ origin của project local và GitHub tự cấp quyền Git, nên không có gì để dùng lại.
  • Cấp Claude auth: Codespaces dựa vào user codespace secret do GitHub inject; Docker cloud không có kênh OAuth được tài liệu hoá (xem 04).
  • Label trung tính: StepKind::label và running_label ("Configure codespace", "Creating codespace"), headline "Starting codespace" trong cloud_start_view.rs, "Delete codespace", "Rebuild this codespace?" đang ghi cứng chữ codespace.

Environment adapter (mới) Official Dev Container CLI, pinned bootstrap versions, build logs, config selection, lifecycle readiness, state path persist qua container rebuild. Credential service (mới) Secret references, scoped delivery/rotation, redaction. Git credential broker và agent auth có contract riêng; không dùng universal token field. Lưu như accounts/token.rs (AES-256-GCM + credentials.key), không Keychain.
Remote session runtime (dùng lại) Prompt/events/approval/cancel/files/Git protocol và durable command receipts. Host package có Node riêng; Node của project không thay thế runtime được pin của Host. Children kế thừa environment của Host (host/child-backend.ts), nên cần scoping credentials trước khi launch.
Archive (dùng lại convert.rs) Chạy convert qua backend seam trước khi xoá sandbox: transcript, evidence, Claude JSONL, bundle/patch code chưa push. Thay gh codespace cp bằng copy qua sbx SSH. Giữ read-only; không reuse remote device token.
Không đồng nghĩa full local parity: remote host hiện có các giới hạn capability, gồm terminal, named provider accounts và một số workflows local (docs/remote-access.md). Cloud session Codespaces bù terminal bằng "Open terminal in codespace" (gh codespace ssh local, vào thẳng container); với Docker ssh <id>@sbx_cloud vào outer sandbox nên cần exec thêm vào devcontainer. Explorer/Changes của cloud session hiện là checkout local (git_gate.rs). V1 dùng capability negotiation, không bật control giả. Browser preview/port forwarding là workstream riêng nếu muốn đưa vào scope; sbx --cloud ports --publish tạo URL public nên không dùng cho Host.
Khác biệt có chủ đích so với Codespaces
  • Codespaces cho nhiều session dùng chung một codespace (CodespaceChoice::Named; archive mặc định Keep khi codespace còn được chia sẻ). Docker v1 là 1 session = 1 sandbox.
  • Codespaces dùng idle timeout 30m và retention 72h (IDLE_TIMEOUT, RETENTION_PERIOD); Docker là wall-clock TTL, mặc định Docker 1h, tối đa 24h kể từ lúc tạo khi gia hạn.
  • Cả hai backend tạo tài nguyên khi user bấm "Create and open". Composer thêm lối vào thủ công cho cả hai; cloud picker ở header menu của Codespaces giữ nguyên.
  • Dữ liệu cũ: remote-projects.v2, remote-sessions.v1, cloud-starts.v1 và trường codespace phải đọc được như cũ; Docker thêm trường mới với serde(default), không đổi tên.
  • Không sửa provider adapters, menu, settings hay transport trong task viết spec này.
07 / DEFINITION OF DONE

Các điều kiện để tính năng được coi là hoàn tất

UX & provisioning

  • Docker dùng lại flow/UI start của Codespaces hiện có: step list StepKind, creation log, error, Retry / Rebuild / Delete và chuyển vào session. Không có wizard, progress card hoặc cloud dashboard mới.
  • Right click project → Cloud setup → Codespaces/Docker; hover, click, keyboard và edge placement đúng. Menu Workspace dưới composer của session mới có mục RUN ON CLOUD (Codespace / Docker Sandbox); cloud picker ở header của Codespaces giữ nguyên. Codespaces setup, cloud picker, start, archive/convert giữ nguyên hành vi; dữ liệu remote-projects.v2, cloud-starts.v1 cũ vẫn đọc được.
  • Dialog Save không charge; chỉ hành động Create rõ ràng của user ("Create and open") mới provision. Thiếu prerequisites có remediation rõ, không cần nhập SSH target.
  • Mỗi feature session mới có đúng một sandbox; retry/restart app không tạo trùng. Mọi create truyền --ttl và --on-timeout stop tường minh.
  • Clone đúng resolved commit, branch/session riêng; local dirty files không bị gửi lên.
  • Ready chỉ khi devcontainer, agent, host và connection đều dùng được.
  • GitHub, GitLab và Bitbucket Cloud đều có smoke test private clone/fetch; write test vào repo test do user cho phép.

Auth, lifecycle & data

  • Process Claude trong sandbox có đúng một trong CLAUDE_CODE_OAUTH_TOKEN / ANTHROPIC_API_KEY theo account đã chọn; ANTHROPIC_AUTH_TOKEN và biến còn lại bị gỡ.
  • Git token lưu AES-256-GCM với credentials.key như account Claude; archive dùng dialog chung, mặc định Stop.
  • Profile dùng lại được qua nhiều sandbox; account password/Git SSH không xuất hiện trong v1.
  • Token không lộ trong argv, logs, Git config, tracked files hoặc archive. Rotation/revocation có hành vi xác định.
  • Prompt/approval/cancel/files/Git hoạt động theo host capability; reconnect không nhân đôi lệnh.
  • Stop xác nhận trạng thái; resume cùng sandbox/workspace/history, xử lý operation bị ngắt rõ ràng.
  • Archive đọc được sau khi sandbox xoá, gồm attachments cần thiết và bundle/patch code chưa push (như convert.rs); thiếu sync chặn auto-delete.
  • Delete chỉ đúng tài nguyên session, không tự push hoặc xoá remote branch; các sandbox khác không bị ảnh hưởng.
Release gates chưa qua: Claude OAuth qua Docker proxy; cách app lưu/chuyển subscription credential được phép; Git credential helper outer/inner hoạt động khi desktop disconnect; private registry flow; Host trong devcontainer + private tunnel; archive sau delete; API key/placeholder trong sandbox không override auth đã chọn; network policy mặc định của account cho phép các destination cần thiết. PoC devcontainer đã pass không thay thế các kiểm chứng này. Kết luận điều khoản về chuyển subscription token cũng áp dụng cho flow Codespaces đang ship.

Đã chốt thêm ngày 08/11/2026

  • Điểm vào: menu Workspace dưới composer của session mới có thêm nơi chạy Codespace / Docker Sandbox, để user tự tạo cloud session thủ công, không phụ thuộc Mono. Cloud picker ở header menu của Codespaces giữ nguyên.
  • Thời điểm tạo: một hành vi cho cả hai backend, theo Codespaces: "Create and open" tạo tài nguyên ngay, session có ngay với step list đến Ready, prompt gõ trong lúc chờ được queue.
  • Archive/xoá: dùng chung dialog "Archive cloud session?" của Codespaces (Keep running / Stop / Delete, mặc định Stop); label theo backend ("Stop sandbox", "Delete sandbox" cho Docker, giữ "Stop codespace", "Delete codespace" cho Codespaces).
  • Nơi lưu Git token: AES-256-GCM trong SQLite + credentials.key như accounts/token.rs; không Keychain (tránh hỏi mật khẩu sau mỗi lần upgrade app).
  • Claude auth: dùng account Claude đã cấu hình trong app. Setup-token → CLAUDE_CODE_OAUTH_TOKEN, API key → ANTHROPIC_API_KEY; adapter chỉ đặt đúng một biến cho process Claude, gỡ biến còn lại cùng ANTHROPIC_AUTH_TOKEN. Không login trong sandbox. Vẫn giữ release gate ở mục 04 và 07.
  • Bitbucket: chỉ API token có scope, không app password. Scope GitLab/Bitbucket/GitHub là việc của user khi tạo token; app chỉ gợi ý và kiểm tra read.
  • Docker account/billing: user tự chuẩn bị (sbx login, setup SSH, credits hay thanh toán); app chỉ kiểm tra và hướng dẫn.

Còn chờ quyết định

  1. Thu hẹp v1. GitLab self-managed, Bitbucket, private registry, Compose và submodules đều là compatibility test riêng. Cân nhắc v1 = GitHub + GitLab.com với image/Dockerfile/Features, phần còn lại là v1.x.
  2. Files/Git của sandbox. Cloud session Codespaces hiện giữ Explorer/Changes ở checkout local và khoá Git write (git_gate.rs). Nếu Docker dùng lại nguyên mô hình này, user không xem/commit được thay đổi của agent trong app trước khi archive. Quyết định: chấp nhận cho v1 (review qua transcript + archive bundle/patch) hay nối Explorer/Changes vào host như remote project thường.
  3. Claude account picker. Đã chốt dùng account trong app (xem trên); chỉ còn mở chuyện cố định theo sandbox hay chọn theo session. Remote host chưa hỗ trợ named provider accounts; chọn account nào thì app phải đặt biến tương ứng vào env của Host trong sandbox (Host chỉ truyền env nó được start cùng cho Claude). Chọn: một account cố định cho mỗi sandbox (đổi account thì restart Host như flow token-hash của Codespaces), hay làm thêm phần chọn account theo session ở host.
  4. App API / Mono. sessions.start với target codespace và các action codespaces.* (mono/cloud_api.rs) đã có cho Codespaces. Cần quyết định Docker v1 có parity ở app API hay chỉ UI; nếu có thì Mono có thể tạo tài nguyên trả phí, cần cùng cost notice.
  5. Template / move. Docs Docker cảnh báo credential ghi trong sandbox có thể nằm trong template và snapshot của sbx move. Đề xuất v1 không dùng template save/move cho sandbox của Monoptah.
